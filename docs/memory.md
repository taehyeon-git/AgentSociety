# 구조화 기억

`agentsociety-memory`는 실제 이벤트를 에이전트별 경험으로 변환하고 제한된 문맥을 검색합니다. 계좌·시장·난수 상태는 변경하지 않습니다. 모델의 제안이나 미체결 주문을 거래 성공으로 기록하지 않습니다.

| 종류 | 현재 기록되는 내용 |
| --- | --- |
| Episodic | 생산, 소비와 용도, 실제 이동, 행동 거절 |
| Economic | 실제 중앙·협상 체결 수량·단가·상대방·매수/매도 관점, 장기 계약 생애주기·납품·종료, 실제 재고 손실·납세·재분배 |
| Social | 양자 제안·역제안·수락·거절·철회·만료, 완료 협력의 상대와 받은 몫, 관계 갱신·제거, 조직 설립·가입·출자·탈퇴·제조·배당 |
| Goal | 생성 시 배정된 목표, 실제 변경된 이전·새 목표와 사유 |

목표 변경은 `GoalChanged`에서 중요도 95, 제안 이력은 55, 완료 협력은 80으로 기억합니다. 양자 협상에서는 제안 기억을 거래 성공으로 취급하지 않으며 수락 후 `NegotiatedTrade`에만 양쪽의 거래 기억을 만듭니다. 거래 기억의 수량×가격은 현금 거래액이고, 원가를 뺀 실현이익을 의미하지 않습니다. 목표 적응의 성과 집계는 별도 `GoalProgress`에 보관하므로 오래된 기억의 제거가 행동 결과를 바꾸지 않습니다.

v0.6의 `Organization`, `Contract`, `Scenario` 기억은 실제 이벤트 내용과 연결되며 중요도는 각각 65, 75, 60입니다. 계약 제안·수락·종료도 Economic으로 분류하지만 실제 거래는 `ContractEvent::Delivered`로 구분합니다. 불이행 보상은 재고 납품이나 판매 매출이 아닙니다. 조직 제조는 공동 재고의 생산이며 노동자 개인이 같은 생산물을 받은 것으로 기록하지 않습니다.

## 보관과 출처

각 `MemoryRecord`에는 원본 이벤트 sequence를 사용하는 `MemoryId`, 소유 AgentId, Tick, 0~100의 중요도, 타입이 지정된 내용이 있습니다. 내용의 `event_type`에서 종류·관련 자원·관련 에이전트를 유도하므로 서로 모순되는 중복 태그를 저장하지 않습니다. `(agent_id, id)`가 고유 키입니다. 양쪽 거래 참여자는 같은 원본 이벤트에 연결된 서로 다른 관점의 기억을 갖습니다.

조직·계약·시나리오 기억은 이벤트에 기록된 참여자에게만 생성합니다. 조직 제조는 실제 노동자, 배당은 수령 회원, 공동 계약은 모든 관련 소유자에게 기억을 남깁니다. 재고 손실·납세는 영향을 받은 계좌의 소유자, 재분배는 실제 수령자에게 기록합니다. 개입 시작·공급 복귀 같은 전역 공지는 개인 참여자가 없어 모든 에이전트의 사적 기억으로 복제하지 않습니다. 계약 기억에는 계약 자원, 재고 손실에는 손실 자원, 조직 제조·배당에는 Goods 관련도 태그가 있으며 조직·계약·시나리오 기억에는 단일 상대방 관련도 태그를 부여하지 않습니다.

`memory_capacity`의 기본값은 에이전트당 64개이고, 0은 기록을 끕니다. 최대 설정값은 1,024개입니다. 보관 한도를 넘으면 가장 오래된 기록부터 제거합니다. 초기 Goal 기억도 오래 실행하면 제거될 수 있지만 에이전트의 현재 목표는 별도 상태로 유지합니다. 같은 source sequence를 두 번 기록하는 것은 오류입니다.

완료 Tick의 이벤트 번호가 확정된 뒤 기억을 기록합니다. 초기 생성 이벤트는 Tick 0에 기록합니다. 기억에도 벽시계 시간을 사용하지 않습니다. 전체 상태 JSON에 포함되며 직렬화 왕복 및 동일 입력 결정론 테스트를 통과해야 합니다.

## 검색

`MemoryQuery`는 현재 Tick, 종류, 관심 자원·상대방, 최소 중요도, 최대 경과 Tick, 결과 수를 받습니다. 미래 기록과 다른 소유자의 기록은 제외합니다. 종류·중요도·경과 시간은 필터이고 자원·상대방은 관련도 가점입니다.

정수 점수는 다음과 같습니다.

```text
2 × importance
+ floor(100 / (min(age, 100) + 1))
+ 200 (관심 자원과 일치)
+ 250 (관심 상대방과 일치)
```

동점이면 더 최근 Tick, 더 큰 이벤트 sequence 순입니다. 저장 순서를 변경하지 않고 별도 결과를 반환합니다. 기본 결과 수는 8개이며 호출자가 큰 수를 요청해도 최대 16개만 반환합니다. 0은 빈 결과입니다.

Inspector의 `Memories`에서 종류별 검색을 볼 수 있습니다. LLM 문맥은 동일 검색을 사용하며 에이전트의 식량 수요 또는 직업 관련 자원을 우선합니다. 별도의 32KiB 문맥 제한도 적용하므로 전체 기억이나 전체 월드를 보내지 않습니다.
