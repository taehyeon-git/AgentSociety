# 조직·공동 재산·장기 납품 계약

v0.6의 `InstitutionBook`은 개인 계좌와 별개의 공동 계좌, 회원 색인, 진행 중 납품 계약을 관리합니다. `organizations.enabled`의 기본값은 `false`이며 `examples/complete.json`에서 활성화합니다. 모든 의도는 규칙·LLM·외부 입력에 같은 검증을 적용하고, 실패하면 관련 계좌·회원·계약 ID를 함께 유지합니다.

## 공개 정관과 공동 소유

`Found`와 `Join`은 개인의 가용 현금에서 정해진 가입금 `membership_stake`를 공동 계좌로 옮깁니다. 새 돈을 만들지 않습니다. 기본 가입금은 200, 최대 회원은 8명이며 3~16명으로 설정할 수 있습니다. 한 사람은 한 조직에만 가입할 수 있습니다. 설립자는 대표자가 됩니다.

회원은 현재 공동 재산을 동일한 지분으로 소유합니다. `Contribute`로 가용 현금·재고를 출자할 수 있지만 출자액에 따른 우선 인출권은 없습니다. 대표자는 `Distribute`로 모든 회원에게 같은 현금·Goods 배당을 지급할 수 있습니다. 한 명이라도 지급이 실패하면 배당 전체가 적용되지 않습니다.

`Leave`는 보유 현금과 자원 각각을 회원 수로 나눈 몫을 반환하며 나머지는 조직에 남깁니다. 마지막 회원은 모든 잔여 자산을 가져가고 조직이 해산합니다. 대표자가 나가면 가장 작은 회원 ID가 새 대표가 됩니다. 해산한 공동 계좌의 매출·구매·이체 이력은 자산이 없는 `retired` 계좌에 합쳐 전체 회계 감사를 유지합니다.

조직에 대기 중이거나 수락된 계약이 있으면 가입·탈퇴를 막습니다. 계약 당사자인 조직의 소유자와 대표가 이행 도중 바뀌지 않도록 한 규칙입니다. 조직이 자기 회원이나 소유자가 겹치는 다른 당사자와 거래하는 계약은 거절합니다.

## 정기 공동 제조

가입은 정관의 공동 노동에 동의하는 행동입니다. `(tick + organization_id) % production_interval == 0`인 시점에 제조를 시도합니다. 기본 주기는 4 Tick입니다.

- 회원 3명 이상, 공동 Wood 4·Metal 2가 필요합니다.
- 노동자마다 가용 Food 3 이상, 에너지 5 이상이 필요합니다. Producer 한 명과 나머지 회원 두 명을 안정적인 ID 순서·Tick 순환으로 고릅니다.
- 세 사람은 각각 에너지 5를 사용하고 공동 재고의 Wood 4·Metal 2를 소비해 공동 Goods 6을 만듭니다.
- 개인 주 행동 뒤, 중앙 시장 정산 전에 실행합니다. 조건을 충족하지 못하면 비용·생산이 발생하지 않습니다.
- 생산 결과는 공동 계좌에 남으며 자동으로 개인에게 지급하지 않습니다. 배당이나 계약 판매로 이전할 수 있습니다.

기존 두 사람의 제안 기반 제조는 별도로 유지됩니다. 그 제조법은 Goods 4를 두 사람에게 직접 나누며, 다자 제조의 생산량·노동량과 구분합니다.

## 분할 납품 계약

`Party`는 `{"kind":"agent","id":1}` 또는 `{"kind":"organization","id":0}`입니다. 조직을 대표하는 의도는 해당 대표자만 낼 수 있습니다. 개인 또는 조직당 대기·진행 계약은 최대 4개, 같은 당사자 쌍의 열린 계약은 1개입니다.

```json
{
  "action": "institution",
  "operation": {
    "kind": "offer_contract",
    "organization": 0,
    "counterparty": { "kind": "agent", "id": 5 },
    "side": "buy",
    "resource": "wood",
    "quantity": 1,
    "unit_price": 70,
    "deliveries": 4,
    "interval_ticks": 4
  }
}
```

가격과 회당 수량은 각각 1~1,000,000, 납품 횟수는 2~32, 간격은 1~64 Tick입니다. 제안 기한은 생성 Tick + 4이며, 만든 Tick에 바로 응답할 수 없습니다.

매수자는 남은 납품 전체 대금을 예약합니다. 매도자는 전체 계약 대금의 10%를 올림한 현금 보증금을 예약합니다. 제안 단계에서는 제안자 몫만 예약하고 `AcceptContract`에서 상대가 자신의 몫을 예약합니다. 매도자의 미래 물량은 미리 예약하지 않으므로 생산·소비·재고 충격에 따라 불이행할 수 있습니다.

첫 납품은 수락 Tick + 간격입니다. 개인 행동·공동 제조·중앙 주문 만료 뒤에 해당 회차를 정산합니다. 물량이 있으면 실제 재고·대금만 이동하고 다음 회차 자금과 보증금은 계속 예약합니다. 마지막 납품이 끝나면 보증금을 해제합니다.

물량이 부족하면 계약을 `Defaulted`로 닫습니다. 남은 매수 대금을 해제하고 매도자의 예약 보증금을 매수자에게 보상금으로 이체합니다. 납품하지 않은 물량은 거래량·매출에 기록하지 않습니다. 진행 중 계약은 일방 철회할 수 없고, 대기 제안의 거절·철회·만료는 제안자 예약을 반환합니다.

## 정책·통계·복원

규칙 정책은 식량·에너지를 우선하고, 여력이 있을 때 조직 가입·출자·배당과 4회 납품 계약을 선택합니다. 계약 응답은 관찰 가격, 보유 자원·현금과 필요 자원을 비교합니다. LLM에도 최대 8개 공개 조직·8명 개인 상대·8개 관련 계약을 제공하며 전체 타인의 기억은 전달하지 않습니다.

`organizations_formed`, `group_productions`, `contracts_offered`, `contract_deliveries`, `contract_defaults`, `compensation`을 기록합니다. 실제 계약 납품은 전체 `trade_count`, `trade_value`, 거래량과 중앙/협상/계약 체결의 합산 VWAP에 포함됩니다. 보증금 보상·출자·배당은 일반 이체로 구분합니다.

공동 현금·재고는 총량에 한 번만 포함합니다. 개인 Gini·평균 자산·분위수·목표 검토에는 각자의 공동 지분을 더합니다. 정수 평가의 나머지는 회원 ID 순서로 배분합니다. 정부 금고는 총 화폐·총 평가 자산에 포함하지만 개인 자산 분포에서는 제외합니다.

진행 계약의 남은 납품 수·다음 시점·보증금, 공동 계좌·회원·대표·해산 이력을 체크포인트에 저장합니다. 개인의 예약 현금은 양자 제안과 장기 계약을 합쳐 대조하고, 공동 계좌는 해당 계약만 대조합니다. 계약 이벤트의 참여자 목록에는 모든 소유자가 들어가므로 대표자가 아닌 회원의 SQLite 이력에서도 공동 계약을 조회할 수 있습니다.
