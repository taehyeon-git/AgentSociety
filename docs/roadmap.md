# 구현 범위와 검증 현황

현재 엔진은 **0.6.0 / 상태·이벤트 포맷 6**입니다. 원문 요구사항의 Phase 1~4와 고급 확장인 협상·목표 적응·다자 조직·공동 재산·장기 계약·위기 및 세금 시나리오를 구현했습니다. GUI 파일 선택·저장·복원, 미래 시나리오 분기, 정책 비교 실험도 제공합니다. 아래 Phase 1~5의 숫자는 당시 검증 이력이며, 2026-11-27 재검증 결과와 환경 제약은 [validation.md](validation.md)를 기준으로 합니다.

## Phase 1 — CLI MVP

- [x] 7개 패키지의 Cargo Workspace와 공개 API 문서
- [x] 기본 ECS World, 고유 에이전트, 4개 직업, 4개 자원
- [x] 목표/성격/기술이 반영되는 규칙 정책
- [x] 단일 스레드 Tick, 검증과 상태 변경 분리
- [x] 원자적 정산, 예약, 가격/시간 우선 매칭, 부분 체결/만료
- [x] 자동 소비, 제조 투입 구분, 전 Tick 화폐/자원 보존 검사
- [x] CLI, 고정 시드, 통계, 선택적 JSONL/CSV/JSON 내보내기
- [x] 최종 fmt/clippy/test/build 통과 (테스트 34개)
- [x] 100명·1,000 Tick 실제 CLI 실행과 동일 입력 재현 확인
- [x] 10/100/1,000명 성능 측정 및 결과 기록

최종 구현은 bevy_ecs 0.19.1을 사용합니다. 로컬 캐시와 MSVC 링커가 없던 초기 환경은 작업 폴더 안의 공식 의존성/CRT 배포 파일, Rust의 rust-lld, 기존 Windows SDK로 해결했습니다. 시스템 전역 Rust나 Visual Studio 설치는 변경하지 않았습니다.

- [x] 기억 기능이 경제 결과·난수·이벤트를 바꾸지 않는 회귀 테스트, Inspector 표시
- [x] 선택적 `llm` feature의 Tokio/Reqwest, Ollama/OpenAI 호환 어댑터
- [x] Llm/Hybrid와 RuleBased 에이전트 혼합, CLI와 GUI의 정책·공급자 설정
- [x] 엄격한 행동 JSON, 현금·재고·에너지 검증, 문맥·응답·설명 크기 제한
- [x] 실행/Tick별 호출 예산, 동시성, 호출 간격, 전체 배치 마감 시간, 실패 시 규칙 대체
- [x] 환경변수 자격증명, 민감 헤더 마스킹, 기록에서 키·HTTP 오류 본문 제외
- [x] `ExternalDecisionRecorded`, Inspector AI 결과, 공급자가 보고한 토큰 사용량
- [x] 기록 결정 배치의 재적용 API와 이벤트·기억·최종 상태 일치 테스트
- [x] fmt, 기본/LLM 포함 clippy·test, 전체 기능 Release 빌드, 실제 CLI 실행·재현과 GUI 자동 실행·종료
- [x] 기억·관계를 켠 10/100/1,000명 성능 측정과 JSONL 기록 오버헤드 측정

검증은 Rust loopback HTTP 서버를 사용하며 실제 유료 API나 설치된 Ollama 모델의 판단 품질을 확인한 것은 아닙니다. Phase 3에서는 최초 목표 배정을 기록했고, Phase 5에서 실제 목표 변경 기억과 성과 기반 적응을 추가했습니다.

## 모델의 경계와 선택적 후속 확장

직업 변경·신용·통화 발행·사망·학습 정책 훈련은 현재 모델에 없습니다. 이전 포맷 마이그레이션, 미완료 JSONL 부분 복구, 중단된 실험 행렬의 자동 재개도 지원하지 않습니다. 이는 현재 기능의 완료 조건과 별개의 후속 확장입니다. 기존 포맷은 해당 버전 CLI로 읽고, 중단 복구에는 SQLite를 사용합니다. 실제 유료 LLM 및 설치된 Ollama 모델의 판단 품질은 자동 테스트의 검증 범위가 아닙니다.
