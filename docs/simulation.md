# Tick 진행과 재현성

Tick 0은 초기 상태입니다. 첫 번째 실행 Tick은 1입니다. 시간은 현실 초·연도와 연결되지 않으며 성능 측정용 `Instant`는 경제 상태나 의사결정에 영향을 주지 않습니다.

## 한 Tick의 순서

1. 외부 결정의 AgentId, 배치 대상 Tick, 결과와 Decision의 일관성을 검사합니다. 이 오류는 상태 변경 전에 반환합니다. 선택적 `PolicyRuntime`의 HTTP 수집은 그보다 먼저 완료된 상태를 읽어 수행합니다.
2. 만료된 공급 충격을 복구하고 해당 Tick의 시나리오 개입을 설정 순서대로 적용합니다. 예약되지 않은 재고 손실을 기록한 뒤 활성 공급 배율로 지역 생산 용량을 재충전합니다.
3. 외부 결과가 있으면 `ExternalDecisionRecorded`를 ID 순서로 기록하고 마지막 AI 결과를 갱신합니다. AgentId 오름차순으로 관찰을 만들고 ChaCha8 난수 한 개를 할당합니다. 외부 결정으로 대체해도 같은 개수의 난수를 사용합니다.
4. 모든 결정을 수집한 후 `DecisionRecorded`를 ID 순서로 기록합니다. 이 시점까지 어떤 에이전트의 행동도 적용하지 않습니다.
5. 기한이 지난 양자·장기 계약 제안을 만료시키고 담보를 해제합니다. 시작 에이전트를 `(tick - 1) % population`만큼 순환시킨 순서로 행동을 재검증하고 적용합니다. 에이전트당 주 행동은 하나이며 조직·출자·배당·계약 응답도 포함합니다. 매수·매도는 자산을 예약하는 주문 생성입니다.
6. 정관에 동의한 조직의 정기 공동 제조를 실행합니다. Food, Wood, Metal, Goods 순서로 중앙 시장을 매칭하고 거래를 정산합니다.
7. 모든 중앙 미체결 주문을 만료시키고 해당 예약을 해제합니다. 장기 계약의 납품 또는 불이행·보증금 보상을 정산하고 중앙·협상·계약 체결을 합친 수량 가중 가격을 계산합니다. 아직 끝나지 않은 약속의 담보는 계속 예약합니다.
8. ID 순서로 자동 소비와 욕구를 갱신합니다. 이후 판매세·주기적 현금 부담금을 거두고 해당 주기에는 금고 재원을 개인에게 재분배합니다.
9. 실제 거래·협력·납품·불이행·제안 결과에 따른 관계 이벤트를 추가합니다. 목표 적응이 켜져 있으면 공동 지분을 포함해 구간 성과를 집계하고 검토 Tick에 목표를 갱신합니다.
10. 실제 발생 이벤트로 Tick/누적 수지를 계산합니다. 개인·공동·정부 계좌의 화폐, 생산·소비·위기 손실의 자원 수지, 모든 담보와 거래/일반 이체 합계를 검사합니다.
11. Tick을 확정하고 `TickCompleted`를 추가합니다. 이벤트에 전역 연속 sequence를 붙입니다.
12. 확정된 이벤트에서 개인의 구조화 기억을 생성하고 보관 한도를 적용한 뒤 호출자에게 반환합니다.

중앙 미체결 예약 해제를 자동 소비보다 앞에 배치한 이유는 팔리지 않은 식량이 불필요하게 묶이지 않도록 하기 위해서입니다. 양자 제안은 기한 내 약속을 유지하며 예약 식량을 생활 소비에 사용할 수 없습니다. 최근 행동 이력의 `accepted`는 의도 접수 여부입니다. 실제 결과는 `TradeExecuted`, `NegotiatedTrade`, `CooperationCompleted`에서 확인합니다. 제안 응답 시점과 목표 검토 규칙은 [상호작용 문서](interactions.md)를 따릅니다.

외부 모델의 관찰은 직전 완료 경계에서 수집하므로 다음 Tick의 공급·재고 충격 적용 뒤에 행동이 거절될 수 있습니다. 이 경우 외부 결과와 실제 `ActionRejected`를 모두 남깁니다. 다자 제조는 `Organization::Produced`, 납품은 `Contract::Delivered`, 실제 손실·납세는 `Scenario` 이벤트에서 확인합니다. [조직·계약](organizations.md)과 [시나리오](scenarios.md)의 저장 상태도 Replay 입력에 포함됩니다.

## 자동 욕구 갱신

- 에너지는 매 Tick 1 회복하고 100을 넘지 않습니다. 노동은 5, 이동은 1을 사용하며 Rest는 25를 회복합니다.
- 식량이 있으면 한 단위를 소비하고 기아를 20 감소시킵니다. 없으면 기아가 10 증가합니다. 기아는 0~100입니다.
- 쾌적도는 2 감소합니다. `tick % 8 == agent_id % 8`이고 쾌적도가 80 이하라면 상품 한 단위를 소비해 20을 회복합니다.
- 기아가 80 이상이면 생산/채집량을 절반으로 줄이며 최소 1을 유지합니다. 사망이나 인구 증감은 아직 없습니다.

## 결정론 계약

필요한 입력은 같은 초기 설정, 시드, 규칙/의존성 버전, 외부 결정 `(Tick, AgentId, Decision)` 또는 기록된 `DecisionBatch`입니다. 초기화 난수와 실행 난수는 ChaCha8의 별도 스트림을 사용합니다. 동일 매도 가격에서는 매수자의 상대방 신뢰를 비교한 뒤 제출 Tick과 주문 ID로 동률을 해소합니다. HashMap 순회, 시스템 시각, 비동기 완료 순서는 상태 적용 순서에 들어오지 않습니다. 실제 LLM 출력을 다시 생성하면 달라질 수 있으므로 재현 시 승인 결과와 대체 사유를 포함한 배치를 재사용합니다.

`SimulationSnapshot`과 이벤트에는 성능 시간이 없습니다. `StepTiming`과 CLI 요약의 `performance`는 비교 대상에서 제외합니다. 부동소수점은 Gini·평균·성능 표시 값에만 사용하며 화폐, 호가, 재고, 난수, 행동 조건은 정수입니다. 서로 다른 CPU/컴파일러 간 표시용 부동소수점의 비트 동일성까지 보장하는 형식은 아직 아닙니다. 규칙과 의존성 버전이 달라진 실행도 동일한 결과를 약속하지 않습니다.

## 실패 처리

완료 Tick은 `Simulation::from_snapshot`으로 복원할 수 있습니다. 이 과정은 계좌·수지·보관 한도·참조와 RNG 위치를 검증한 뒤 ECS를 다시 구성합니다. `Simulation::replay_tick`은 기록된 의도를 사용해 한 Tick을 실행하고 모든 이벤트를 원본과 비교합니다. CLI는 이를 JSONL/SQLite 스트리밍 검증과 연결합니다. 런타임 호출 예산은 `RunCheckpoint`가 보관합니다. 자세한 파일 계약은 [저장·복원](persistence.md)에 있습니다.

잔액/재고 부족, 허용하지 않는 행동은 해당 의도만 거절하고 `ActionRejected`와 행동 이력에 이유를 남깁니다. 같은 자원 풀을 여러 에이전트가 경쟁해 뒤쪽 행동이 거절될 수도 있습니다. 새 돈이나 재고를 자동으로 만들어 주지 않습니다.

산술 오버플로, 내부 색인 오류, 보존식 위반은 실행을 중단하는 오류입니다. 거래와 생산 레시피는 원자적이지만 전체 Tick을 복제해 롤백하지는 않습니다. 실패한 Tick의 월드를 계속 진행하거나 정상 스냅샷으로 내보내지 못하도록 엔진을 실패 상태로 고정합니다. 이는 부분 처리 상태를 정상 결과로 오인하지 않도록 하기 위한 계약입니다.

엔진은 호출자가 Step을 요청할 때만 진행합니다. GUI worker가 목표 Tick 속도(1~240/s), 일시정지, 단일 Step, 재시작을 제어합니다. 실제 속도는 Tick 및 선택적 LLM 처리 시간에 의해 낮아질 수 있습니다. HTTP 실패·타임아웃은 규칙 대체로 처리하며, stale 배치는 다음 Tick에 적용하지 않습니다. 핵심 계좌/보존 오류는 여전히 실행 중단 오류입니다.
